Publicering på Netlify

Jag har valt att publicera denna webbplats till Netlify. Framförallt för att jag har använt den ett par gånger tidigare, men också för att vänja mig vid den ytterligare då jag tidigare främst använt GitHub Pages för publicering.

Språk

Netlify stödjer väldigt många olika språk, som HTML, CSS, JavaScript, TypeScript, PHP och många andra.

Det gör den perfekt för den som använder många av dessa programmeringsspråk, men också för den som inte vill göra en flerspråkig webbplats.

Kostnad

Medan Netlify är till stor del gratis att använda så finns det även möjlighet att betala för att få tillgång till fler funktioner.

Storlek

Det finns en gräns för hur stora filer får vara för att kunna laddas upp till Netlify. Maximal filstorlek är 256 MB, men för mindre webbplatser är det inte så vanligt att gå över den gränsen.

Fördelar

  • Det är enkelt att använda: om du redan vet hur du skapar ett repo i GitHub kan du koppla det till Netlify: varje gång du pushar en förändring så kommer det automatiskt att uppdatera webbplatsen som du har i Netlify.
  • Du får snabb återkoppling när något inte fungerar vid start av webbplats eller liknande.
  • Du kan även förhandsgranska innan förändringar blir live.

Nackdelar

  • Som tidigare nämnt, det är inte gratis om du vill A: ha stora filer eller B: använda mer avancerade funktioner.
  • Om trafiken till webbplatsen plötsligt skjuter i höjden kan resurser för denna månad ta slut. Har du betalversionen kan du även få oväntade höga avgifter.

Arbetssättet

Du arbetar lokalt med ditt projekt: du programmerar, felhanterar och så vidare tills du känner dig redo att spara nuvarande version hos exempelvis GitHub.

Via GitHub kan man versionshantera projektet och spara ändringar samt pusha nya filer till projektets repository.

Koppla ditt GitHub konto till Netlify (exempelvis genom att logga in på Netlify med GitHub konto). Väl inne där kan man välja om man vill publicera en webbplats: i detta fall kan man bland annat ange eventuella bygginställningar samt vad man vill att webbplatsen ska heta. Netlify kontrollerar så namnet inte redan är taget.

När kopplingen är klar och webbplatsen fungerar (inga fel som gör att exempelvis länkar inte fungerar som planerat) så håller Netlify GitHub-repot under bevakning. Detta innebär att varje gång nya ändringar pushas till den gren som projektet publiceras från så hämtar Netlify de nya/uppdaterade filerna och uppdaterar webbplatsen automatiskt.

När publiceringen är avklarad kan man lätt kontrollera den webbplatsen via en publik URL som skapas. Man får även publiceringsloggar som kan visa om något har gått fel, så man får bättre återkoppling den vägen i stället för att behöva gissa sig fram.
